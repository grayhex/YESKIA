# Личные данные S60: нативный Rust

На страницах «Контакты», «Сообщения» и «Календарь» приложение читает выбранный
подключённый телефон напрямую. Python, Gammu, профили и внешний Bridge больше не
используются и не включаются в пользовательский сценарий. Снимки хранятся в памяти
страницы, поддерживаются поиск, просмотр и экспорт JSON через системный диалог.
Запись контактов, отправка SMS и двусторонняя синхронизация пока не реализованы.

## Контакты, календарь и задачи

Переписаны `nokia_pccs.py` и `pccs_windows.py` из s60modern (efaf53d, MIT):
SetupAPI перечисляет интерфейсы Nokia USB OBEX `{4F919100-4ADF-11D5-882D-00B0D02FE381}`.
PnP-цепочка каждого интерфейса должна вести к выбранному устройству; интерфейсы
другой подключённой Nokia не используются. Phonet и LCIF не открываются.

Rust выполняет Connect к Folder Browsing target и проверяет Who/ConnectionId.
Далее OpenStore → ResetChangeInfo → GetStoreFormat → SetRemoteStoreFormat →
ListChanges → ReadItems → CloseStore → Disconnect. Контакты запрашивают точные
63 байта формата из источника, календарь возвращает формат телефона без первого
слова. Размер батча — 2 ID: большее число на исходном E72 не проверялось.
Единственный PUT согласует формат; CommitChanges/CreateItems/DeleteItems отсутствуют.
ResetChangeInfo влияет на служебное состояние синхронизации, но не меняет записи.

Поддерживаются OBEX Continue, vCard 2.1, vCalendar 1.0/iCalendar 2.0, события,
задачи, переносы строк, quoted-printable, UTF-8 и явно указанные старые кодировки.
Поля вложенных будильников не замещают поля события. Обрезанный ответ, неверный ID,
повтор ID или неподдерживаемая карточка дают ошибку вместо частичного «успеха».
Ограничения: 8 МиБ суммарных карточек, 20000 ID, 120 секунд на сеанс,
4096 OBEX Continue; USB-запросы ограничены временем и отменяются через CancelIoEx.
Буферы overlapped I/O освобождаются только после завершения отменённого запроса.

В s60modern этот путь проверяли вручную на одном E72. В YESKIA после переписывания
пока подтверждены только пакеты и синтетические сценарии, не физическое чтение.
`tests/fixtures/pccs/` содержит синтетические ответы исходного FakePhone и ожидаемые
запросы исходной Python-реализации. Rust обязан совпадать с ними побайтно.
Личные данные и сырые USB-пути не включаются в журнал.

## SMS

Самостоятельная Rust-реализация 3GPP PDU использует COM-порт того же PnP-устройства,
даже если для файлов доступен WPD. Команды: `AT+CMGF?`, затем `AT+CMGL=4,1`.
Mode 1 запрашивает чтение без изменения статуса unread/read. Если телефон его не
поддерживает, приложение сообщает об этом и не повторяет запрос в меняющем статус
режиме. CMGF не переключается, CMGS/CMGD не отправляются.

Разбираются входящие/исходящие PDU, GSM 7-bit и UCS-2, адрес отправителя и поля
составных SMS. Части пока показываются отдельно. Текстовый режим и бинарные SMS
не поддержаны. Лимиты: 1 МиБ ответа, 5000 SMS, 30 секунд на AT-команду, отмена
между чтениями. Прочитано только текущее хранилище модема; SIM/ME не переключаются.
Доступность Nokia-команд, хранилищ и параметры драйвера требуют аппаратного теста.

## Сертификаты

Раздел читает один публичный CER/DER/PEM до 512 КиБ и показывает сведения, даты,
SHA-256. «Установить на телефон» открывает подтверждение с именем телефона,
владельцем и отпечатком. При подтверждении Rust повторно читает сертификат,
проверяет совпадение SHA-256 с просмотренным файлом и передаёт DER через OBEX
Object Push выбранного телефона, учитывая согласованный размер пакета.

Это путь доставки в телефонный сценарий установки. Пользователь принимает файл,
открывает его на Nokia и подтверждает установку/области доверия. Приложение не
заявляет, что доверие уже установлено, и не меняет хранилище сертификатов Windows.
Потеря ответа после PUT означает неопределённую доставку: автоматического повтора
на другом интерфейсе нет. При отсутствии OPP показывается ошибка, без фиктивного успеха.
Нативный Object Push на E72 в YESKIA ещё не проверен.

## Проверка с телефоном

1. Выбрать PC Suite на разблокированном E72, закрыть Nokia PC Suite на ПК.
2. Подключить в YESKIA; прочитать контакты, календарь и задачи, сверить записи.
3. Проверить два телефона, несколько страниц ответов, русские имена, пустые
   хранилища, будильники, повторения, отмену и USB unplug. Частичных успехов быть не должно.
4. Прочитать SMS, проверить GSM/UCS-2 и составные части; статусы сообщений до/после
   должны совпасть. Если mode=1 не поддержан — ожидается ошибка, не запасной режим.
5. Для сертификата использовать собственный тестовый публичный сертификат. Проверить
   отмену подтверждения, смену файла после просмотра, отказ телефона, unplug во время
   PUT и ручное завершение установки. Не отмечать установку успешной по одной доставке.

## Остальной перенос

Инспектор SIS/подписей/зависимостей, анализ тем, медиа, файловые копии и каталог уже
есть в Rust/React. Код s60modern, который вызывает python-gammu, obexftp, внешние
сборщики или отдельные веб-службы, не является готовым нативным протоколом.
Редактирование PIM, отправка SMS и дополнительные службы требуют собственных
протокольных реализаций и проверки; здесь они не заменены имитацией.
