# AT-канал по виртуальному COM-порту (issue #10)

> **Это не протокол Nokia PC Suite (NPC).** Реальных обезличенных трасс NPC (#6) пока нет, поэтому ни один
> сервис NPC в YESKIA не реализован и не заявляется. Здесь описан **отдельный** канал на открытом стандарте
> 3GPP TS 27.007 / 27.005 (AT-команды), который телефон в режиме PC Suite может предоставлять через
> виртуальный COM-порт. Код и контракт проверены на синтетических диалогах; **на реальном Nokia канал не
> проверялся** (`not-tested`). Статус реализации — `implemented`, не `verified-on-device`.

## Что реализовано (только чтение)

| Команда | Зачем | Что читается |
| --- | --- | --- |
| `AT` | проверка связи | `OK` |
| `AT+CGMI` | производитель | должен содержать «Nokia», иначе порт не считается телефоном |
| `AT+CGMM` | модель | **единственный** источник `identified_model` в этом режиме |
| `AT+CGMR` | версия прошивки | текст, без IMEI |
| `AT+CPBS?` | занятость телефонной книги | **число** записей (`+CPBS: "ME",12,250` → 12), без самих записей |
| `AT+CPMS?` | занятость хранилищ сообщений | **число** сообщений, без текстов |

Набор команд **закрыт** перечислением `at::Query`; строка команды не собирается из пользовательского ввода.
В перечислении нет и не может быть: `AT+CMGS` (отправка SMS), `AT+CMGW/CMGD/CPBW` (запись/удаление),
`AT+CGSN` (IMEI), `ATZ`/`AT&F`/`AT+CFUN` (сброс), `ATE0`, `AT+CPBS="…"`/`AT+CPMS="…"` (смена хранилища),
`ATD`, `AT+CLCK`, `AT+CKPD`. Контрактный тест проверяет, что ни одна команда перечисления не содержит
запретных фрагментов и не содержит `=`. Отправка SMS не выполняется ни в обнаружении, ни где-либо ещё.

Счётчик относится к хранилищу, **выбранному телефоном сейчас** (`"ME"`, `"SM"` …): имя хранилища ядро
получает, но наружу отдаёт только число; выбор хранилища не меняется. Ответ без счётчиков (`+CPBS: "SM"`) —
ошибка, число не выдумывается.

## Кадрирование и ошибки (контракт, `crates/yeskia-core/tests/at.rs`)

- Команда отправляется как `<текст>\r`. Строки ответа разделяют `\r` и `\n` в любых сочетаниях; пустые
  отбрасываются; эхо команды (если есть) пропускается; побайтовая доставка допустима.
- Финальные коды: `OK`; `ERROR`; `+CME ERROR: n`; `+CMS ERROR: n` (текстовый код → «неизвестная» 100).
  `NO CARRIER`/`BUSY`/`NO ANSWER`/`NO DIALTONE` и **`CONNECT`** (режим данных) — нарушение протокола,
  обмен прерывается.
- Незапрошенные коды (`+CIEV`, `+CMTI` …) в ответе на запрос с префиксом отбрасываются.
- Пределы: 4 КиБ и 64 строки на ответ, 512 байт на строку; таймаут команды 4–5 с.
- Классификация: «не поддерживается/не разрешено» (`ERROR`, `+CME 3/4/100`, `+CMS 300–304`) →
  `CapabilityUnsupported` (в матрице `unsupported`); остальные коды (например `+CME 10` — нет SIM) →
  `TransportError` (`error`), а не «не поддерживается»; нет ответа → `Timeout`; потеря порта (в том числе
  посреди ответа) → `DeviceDisconnected`. Отмена и пропажа устройства прерывают обмен.

## Доступность возможностей

`identity.read`, `contacts.read` (число), `sms.read` (число) получают `Available` **только после реального
обмена** на этом соединении: `AT` → `CGMI` (Nokia) → `CGMM`; затем `CPBS?` и `CPMS?`. Телефон может отклонить
один сервис, не скрывая остальные. Если порт занят другой программой (например, Nokia PC Suite) — матрица
показывает причину, ничего не «доступно». Без `with_serial` (не Windows, нет открывателя) COM-режим остаётся
`unsupported` — как до этой задачи. Запись файлов, `contacts.write`, `sms.send`, установка пакетов по этому
каналу `unsupported` и не реализуются.

Порт открывается на время операции и закрывается сразу (`Drop`), параметры линии не меняются, имя порта
проверяется (`COMn`). Ответы в журнал не пишутся.

## Reuse: Gammu и другие библиотеки

Gammu (GPL-2.0-or-later) умеет AT-режим для многих телефонов, но не линкуется в YESKIA (граница GPL, см.
[REUSE_MATRIX.md](../REUSE_MATRIX.md)); код Gammu не копировался. Выбран собственный адаптер на Rust, потому что
нужное подмножество — несколько запросов чтения по открытому стандарту, а контракт (закрытый набор команд,
пределы, классификация ошибок) тестируется без телефона. Сравнение с Gammu на реальном телефоне по
воспроизводимости — отдельная задача после появления устройства. Проприетарный код NPC/драйверов не использовался.

## Как закрыть приёмку на устройстве (нужен собственный телефон)

1. Подключить Nokia E52/E72/N95 в режиме PC Suite; убедиться, что Doctor показывает `com_present`, и закрыть
   NPC/Ovi Suite (порт должен быть свободен).
2. Подключить устройство в YESKIA; в матрице смотреть `identity.read`, `contacts.read`, `sms.read`.
3. Зафиксировать **обезличенный** результат (`yeskia-lab inventory` + заметка: модель, RM, прошивка, режим USB,
   какие запросы приняты), не записывая IMEI, серийник, номера, тексты, имена пользователя Windows.
4. Только после этого — запись в [COVERAGE.md](COVERAGE.md) со статусом `verified-on-device` и ссылкой на отчёт
   (`evidence = adapter-verified`, проверяет `yeskia-lab validate`).
5. Отдельным тестом отключить кабель во время запроса — ожидается `DEVICE_DISCONNECTED`.

## Что дальше (отдельными задачами)

подтверждения на устройстве, с экспортом vCard/iCalendar/CSV после согласия пользователя и без личных данных в

копии, предпросмотра и обратного чтения.
