# Лаборатория совместимости Nokia PC Suite (NPC) — регламент

Цель: повторяемо изучать USB-трафик оригинального Nokia PC Suite / Connectivity Cable на **собственном
телефоне**, чтобы реализовывать в YESKIA только то, что доказано, а не угадывать по VID/PID.
Изучение — **только для совместимости**.

## Границы и конфиденциальность (обязательно)

- Не включать и не распространять бинарники NPC, закрытый код, ключи, прошивки. Лицензии и ограничения
  оригинального ПО соблюдаются; YESKIA — независимый клиент (не связан с Nokia/HMD).
- **Не** реализовывать и не документировать обход аутентификации/защит. Анализ динамических полей
  (`yeskia-lab diff`) — только чтобы отличить счётчики/время от постоянных заголовков; это не способ
  подделки challenge/response.
- **Не публиковать** сырые захваты, IMEI, серийные номера, SMS, контакты, MAC, токены, PnP instance ID,
  имена пользователя Windows. Сырые захваты хранятся **локально** (каталог `lab-captures/`, он в `.gitignore`),
  минимальный срок — 14 дней по умолчанию (не более 90), затем безопасно удаляются.
- В репозитории допустимы только **обезличенные синтетические** фикстуры и отчёты, прошедшие `yeskia-lab scan`
  (запускается в CI и блокирует `*.pcap`, `*.pcapng`, `*.etl` и приватные данные в `docs/protocol`).
- Заявление «протокол поддерживается» допустимо **только** после успешного общения отдельного адаптера YESKIA
  с телефоном (`evidence = adapter-verified` + ссылка на адаптер и устройство). Наблюдения и гипотезы
  такого права не дают — это проверяет `yeskia-lab validate`.

## 0. Подготовка стенда (инвентаризация)

Зафиксируйте в отчёте (`yeskia-lab inventory` заполняет ОС, USB-режим, драйвер и VID/PID автоматически,
остальное — вручную):

| Что | Откуда |
| --- | --- |
| ОС и сборка Windows | `inventory` |
| Модель, RM (код продукта), прошивка телефона | экран `*#0000#` / наклейка (RM — не персональные данные, **IMEI/серийник не записывать**) |
| Режим USB на телефоне | меню телефона; фиксируйте точное название |
| Драйвер (класс, сервис, версия) | `inventory` |
| Версия NPC / Ovi Suite | «О программе» |
| USB VID:PID и интерфейс | `inventory` (`0421:0223` — это идентификатор модели USB, не личные данные) |

**Безопасный эталонный тест.** Перед любыми экспериментами: сделайте резервную копию пользовательских данных,
создайте **отдельные тестовые** контакты/файлы/SMS (заметно искусственные, без реальных имён и номеров).
Запись, удаление и синхронизация — только позже, при наличии копии, отдельного согласия и тестовых данных.

## 1. Захват трафика

Рекомендуемый стенд: **USBPcap + Wireshark** (сырые USB-транзакции); дополнительно — Windows ETW /
`setupapi.dev.log` (события PnP и драйвера). Драйверы **не менять** ради захвата (никаких WinUSB/libusb поверх
Nokia-драйверов) без отдельного обоснования.

1. Подключите телефон в нужном режиме, определите USB-устройство и интерфейс (`yeskia-lab inventory`).
2. Запустите USBPcap на **нужном корневом хабе**, фильтр по адресу устройства; проверьте, что виден именно
   трафик телефона (а не клавиатуры/мыши).
3. **Не смешивайте каналы.** Эксперимент относится к одному каналу и фиксирует его в отчёте:

| Канал | Что это | Как отличить |
| --- | --- | --- |
| `wpd` | MTP через Windows Portable Devices; в Windows — без COM и без буквы диска | `inventory`/Doctor: состояние `wpd_only`; PC Suite при этом не работает |
| `pc_suite_serial` | Виртуальный COM-порт (режим PC Suite) | Doctor: `com_present`/`com_busy`; в захвате — USB CDC/serial, а не MTP-контейнеры |
| `usb_raw` | Сырой USB-захват (bulk/control/interrupt) любого режима | USBPcap; указывайте endpoint и тип передачи |
| `bluetooth` | Bluetooth/OBEX | отдельный стенд |

4. Перед каждым действием поставьте **time-marker** (например, записью в журнале с точным временем или
   `Marker` в фикстуре): «UI: connect», «UI: identify» и т. д.

## 2. Одно действие за эксперимент (порядок)

`enumerate / handshake` → `identity` → `list folders` → `read file` → `contacts read` → `calendar read` →
`SMS read`. Только чтение. Каждое действие — отдельный эксперимент и отдельный отчёт. Запись/удаление/синхронизация
— позже (см. «Безопасный эталонный тест»).

## 3. Обработка и обезличивание

1. Сырой захват остаётся в `lab-captures/` (локально). Экспортируйте в JSON Lines формата `yeskia.lab.fixture/1`
   (заголовок + кадры + маркеры).
2. Маскирование полезной нагрузки с сохранением длины и первых N байт заголовка:
   `yeskia-lab redact-fixture вход.jsonl выход.jsonl --keep 4` (текстовые серии ASCII/UTF-16 заменяются).
3. Текст (логи, заметки): `yeskia-lab redact-text вход.txt выход.txt` — IMEI/идентификаторы, серийники, MAC,
   пути устройств, e-mail, телефоны, длинные токены, имя пользователя Windows.
4. **Ручная проверка** результата человеком обязательна для реальных данных (`reviewed_by_human: true`).

## 4. Анализ

- `yeskia-lab analyze fixture.jsonl` — обмены «запрос → ответ», задержки, **повторы** (retry), **сбросы**
  шины, гипотеза **framing** (поле длины: смещение, размер, порядок байт).
- `yeskia-lab diff a.jsonl b.jsonl` — байты, отличающиеся между двумя сессиями одного сценария: кандидаты в
  динамические поля (счётчик, время, nonce, challenge) против постоянных заголовков.
- Сопоставляйте метки UI по времени с обменами и направлением endpoint. Любой вывод анализатора — уровень
  `inferred`; поднять его до `observed`/`adapter-verified` можно только по правилам выше.
- **Реплей-тесты**: фикстура + эталонный результат анализа (`*.golden.json`) проверяются в CI
  (`crates/yeskia-lab/tests`), поэтому разбор воспроизводим на обезличенных данных.

## 5. Отчёт эксперимента

Формат — `yeskia.lab.report/1` (JSON), шаблон — [templates/experiment-report.md](templates/experiment-report.md),
пример (синтетический) — [cases/CASE-0001-synthetic-enumerate-identify.report.json](cases/CASE-0001-synthetic-enumerate-identify.report.json).
Обязательно: setup, тестовые данные, действие и канал, параметры захвата и редакции, **выводы с уровнем
доказательств**, **«что известно»**, **«что неизвестно»**, **следующий конкретный эксперимент**.
Проверка: `yeskia-lab validate отчёт.report.json`. Заготовка по реальному стенду: `yeskia-lab inventory --out отчёт.report.json`
(поля `TODO` обязаны быть заполнены, иначе валидатор не пропустит).

Уровни доказательств: `observed` (видно в захвате) · `inferred` (вывод/эвристика) · `hypothesis` (нужен эксперимент) ·
`adapter-verified` (подтверждено адаптером YESKIA на реальном телефоне; требует `adapter_ref`).
