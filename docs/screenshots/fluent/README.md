# Fluent UI verification

Снимки сделаны из работающего React/Vite UI в Chromium, а не из HTML-прототипа.
Браузер использует явно помеченный MockBackend. Физическая Nokia и Windows
WebView2 в этом прогоне не использовались; аппаратная поддержка не подтверждается.

- `home|files` — главная или файловый менеджер.
- `mock` — подключённый демо-телефон E72; `empty` — демо-устройство отключено
  в настройках, список устройств пуст. Браузерный демо-баннер остаётся видимым.
- 1500×900 / RU и 1366×768 / EN, обе системные темы: 16 основных фактических снимков; `section-*.png` — ещё 8 рабочих
  разделов в светлой теме RU.
- На каждом размере дополнительно проверены эффективные рабочие области
  при 100/150/200%: viewport делился на коэффициент масштаба, а deviceScaleFactor
  умножался на него. Это проверка адаптации к DPI, не запуск Windows с реальным DPI.
- На 48 комбинациях главная/файлы/состояние/размер/тема/масштаб проверены
  отсутствие горизонтального переполнения body/main, загрузка изображений и
  отсутствие ошибок JavaScript. Дополнительно открыты остальные разделы.
- Reduced motion включён; клавиатура, ограничение корня в breadcrumbs,
  сброс выделения, доступность быстрых действий, журнал сессии, коллизии,
  отмена и read-only ограничения покрыты UI-тестами.

До: пастельная палитра Soft UI, декоративная коллекция на главной, путь одной
строкой. После: Nokia Blue, текстовое название YESKIA, группы навигации,
выбранная модель E72, проверенные возможности и журнал, интерактивные пути
и таблицы в двух панелях. Контакты, SMS и прочие разделы используют общие
Fluent-компоненты без расширения возможностей транспорта.

Предыдущие снимки: `../soft-home.png`, `../soft-certificates-en-dark.png`.

Финальная сверка с графическими превью: приглушённый градиент центральной
карточки, более крупный E72 с частичным кадрированием, три компактных показателя,
светлая боковая область, порядок разделов и нижняя группа настроек,
панель рабочего пространства, облегчённые границы кнопок и файловых панелей.
Демонстрационные числа/история из макета не перенесены в рабочий UI.

Проверки: `npm run ui:test` (125 тестов), `npm run ui:typecheck`,
`npm run ui:lint`, `npm run ui:build`; `cargo test -p yeskia-core --test engine`
(36 тестов). Rust-изменение ограничено именем и идентификатором mock E72.

Дополнительная сверка акцентов: общие SVG-иконки и цветные подложки используются
в заголовках панелей всех разделов, быстрых действиях, состояниях и показателях.
Файлы различаются пиктограммами папки/изображения/музыки/пакета; очередь и журнал
используют семантические маркеры. Градиент центральной карточки дополнительно
приглушён до графитово-синего. Четыре плитки повторяют акценты превью: файлы —
синий, копии — зелёный, приложения — фиолетовый, медиа — янтарный. Локальные
каталог и студия открываются без телефона; доступ к файлам/копиям определяется
матрицей возможностей. В снимках mock выполнена реальная для MockBackend
операция идентификации, поэтому журнал содержит её фактический результат.
