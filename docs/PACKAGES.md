# Офлайн-пакеты: библиотека, инспектор, передача (issue #8)

> **Это статический анализ файлов.** Приложение **не устанавливает** пакеты, не запускает их содержимое
> и не утверждает, что пакет «совместим» или «установится». «Передать на телефон» — это запись файла
> (`packages.transfer`) с проверкой обратным чтением; установку и её результат пользователь проверяет на
> Nokia. Всё работает офлайн: сети, облака и скачивания нет.

Источники логики — модули SymPort `symport/sis`, `symport/inspector`, `symport/catalog/packages.py`,
`symport/deps` и документы CERTIFICATE_INSPECTOR / DEPENDENCIES (MIT, «SymPort contributors»); код
переписан на Rust (`crates/yeskia-core/src/pkg`, `library.rs`), Python-sidecar не нужен.

## Библиотека

- Хранилище: `<данные>/library/library.sqlite` и `library/files/<SHA-256>`. Файлы хранятся **без
  расширения** и не исполняются; исходное имя — только метаданные (проверяется как имя Windows, путь отбрасывается).
- Импорт через нативный диалог «Добавить файлы…» (SIS, SISX, JAR, JAD; 1 байт — 32 МиБ; до 5000 пакетов).
  Идентификатор пакета — SHA-256; повторный импорт тех же байтов — одна запись.
- Нечитаемые и повреждённые файлы **сохраняются со статусом** (`unreadable`/`corrupt`), чтобы пользователь
  видел причину; передать их на телефон и использовать как поставщика зависимостей нельзя.
- Поиск (имя, название, вендор, UID, SHA-256; кириллица), фильтры: формат, набор, модель телефона.
  Фильтр по модели показывает **заявленную** платформу из пакета (`declared` / `not-declared` / `unknown`);
  это не проверка установки. Для S60 2nd Edition (Nokia 7610) всегда `unknown`.
- Наборы приложений: именованные упорядоченные списки пакетов (до 200 наборов × 200 пакетов).
- Происхождение и права вводит пользователь (источник, ссылка, лицензия, заметка, флажок «вправе хранить и
  передавать»); приложение их **не проверяет**, по умолчанию права `unknown`.
- Целостность хранилища: перед анализом и передачей SHA-256 файла сверяется с идентификатором.

## Инспектор (`yeskia.inspector/1`)

SIS/SISX: UID-заголовок и его контрольное слово, CRC16 контроллера и данных (отсутствующее необязательное
поле → `null` = «не проверено», не «верно»), структура контроллера (хранится или zlib), список файлов и
SHA-1 каждого встроенного файла, имя/вендор/версия, предварительные условия (платформы и зависимости с
диапазонами версий), число цепочек подписей. Лимиты: 128 МиБ распакованных данных, 100 000 элементов в
массиве, 32 МиБ на пакет; 64-битные длины и ненулевое выравнивание отвергаются.

Подписи (`cert.rs`): математика RSA/SHA-1 и RSA/SHA-256 подписи контроллера, цепочка сертификатов
(RSA SHA-1/256/384/512, ECDSA P-256/P-384), самоподписанный корень, даты сертификата **на заданный момент**
(не «сейчас» по умолчанию скрытно). Доверие телефона — всегда `unknown`, отзыв — `not-checked`,
привязки IMEI/SID/capabilities — `not-verified`. SHA-1 помечен как устаревший. DSA/SHA-1 → `unsupported`
(в SymPort он проверялся; здесь честно «не поддерживается»).

E32 внутри пакета: CPU, ABI, ядро (EKA1/EKA2), сжатие, SID/VID, список возможностей (capabilities) и
ограниченные из них. **Импорты не декодируются** (`imports: null`, замечание `imports-undecoded`): отсутствие
найденных зависимостей ничего не доказывает.

JAR/JAD: ZIP с лимитами (≤10 000 записей, ≤64 МиБ после распаковки, без `..`/абсолютных/дублей, CRC каждой
записи), манифест (≤64 КиБ, дубликаты ключей запрещены, секции подписей не читаются), обязательные ключи
MIDlet-*, сверка JAD↔JAR (имя файла, размер, имя/версия/вендор).

### Итог совместимости

`compatible` **не выдаётся никогда**: для этого нужны профиль прошивки и проверенная модель. Итог —
`incompatible` (повреждён пакет, неверная подпись, платформа/CPU/ядро явно не подходят, зависимость
библиотеки старее требуемой) или `unknown`. Зависимости: `required-unverified` (по умолчанию),
`provided-in-library` (UID есть среди пакетов библиотеки — это не «установлено на телефоне»),
`provided-version-too-old`; вердикт `no-declared-dependencies` / `unresolved` / `provided-in-library` /
`blocked` — «satisfied» нет. Платформы (`S60ProductID`): таблица UID с источниками (`pkg/profile.rs`),
профили моделей — из реестра s60modern. Установка, эмулятор и физический телефон — всегда `not-tested`.

Диагностика сообщения установщика (`diagnose`) — эвристика по тексту, результат помечен как такой.

## Передача на телефон

Операция Engine `packages.transfer` доступна ровно тогда, когда доступна запись файлов на соединении
(`files.write`); на WPD/MTP запись не заявляется, поэтому кнопка неактивна с объяснением. Перед записью ядро
сверяет SHA-256 файла с подтверждённым (изменение между проверкой и записью → отказ), перезапись запрещена,
допустимы только имена `.sis/.sisx/.jar/.jad`, затем читает записанное обратно и сверяет хеш. Исход сбоя
записи `uncertain`, автоповтора нет — как у остальных записей. Автоустановки и прошивки нет.

## Что не перенесено и почему

- HTTP-каталог SymPort (`catalog/`, downloader, проверка по URL): ссылки на сторонние дистрибутивы с разными
  лицензиями и сетевая загрузка противоречат офлайн-дизайну; свои пакеты пользователь добавляет сам и указывает
  происхождение и права. Офлайн-манифест каталога можно добавить отдельной задачей после проверки лицензий.
- Профили прошивок и таблицы экспортов DLL (Firmware Explorer), декодирование импортов E32 — нужны отдельные данные.
- Комплекты (bundle ZIP с INSTALL.txt), эмулятор-тест, Jailbreak Manager — вне задачи.
- Перетаскивание файлов из Проводника в окно: в окне отключён `dragDropEnabled` ради перетаскивания между панелями
  файлового менеджера (docs/FILE_MANAGER.md); файлы добавляются нативным диалогом.

## Отличия от SymPort и сверка поведения

`crates/yeskia-core/tests/golden/symport_python_reference.json` — вывод Python-реализации SymPort
(`reader.inspect` и `inspect_signatures`) на тех же байтах фикстур SDK (`tests/fixtures/pkg`, см. README
там), снятый на дату 2026-11-10; тесты `sis_structure_matches_symport_python_reference` и
`signatures_match_symport_python_reference` сравнивают поля поштучно. Расхождения (намеренные):

| Что | SymPort | YESKIA |
| --- | --- | --- |
| Имя типа ключа | `RSAPublicKey` | `RSA` |
| DSA/SHA-1 подпись | проверяется | `unsupported` |
| Итог `compatible` | возможен при профиле прошивки | не выдаётся |
| Повреждённый пакет | отказ импорта | сохраняется со статусом `corrupt` |
| Импорты E32 | декодируются (несжатые) | не декодируются |
| «Предоставлено комплектом» | `provided-by-bundle` | `provided-in-library` |

## Лицензии

SymPort — MIT; фикстуры собраны SDK symbian-platform (Apache-2.0). Новые зависимости: `flate2`, `sha1`,
`x509-parser` (+ `der-parser`, `asn1-rs`, `oid-registry`) — MIT OR Apache-2.0; `zip` — MIT; `ring` —
Apache-2.0 AND ISC (используется только для проверки подписей).
