# Локальные резервные копии файлов (issue #7)

> **Это файловая копия, а не полный backup телефона.** В неё не входят контакты, SMS, календарь,
> реестр установленных приложений, диск C:\ телефона и прошивка — пока отдельный транспорт не подтвердил
> доступ к ним (см. [STATUS.md](STATUS.md)). Баннер с этим текстом показан на странице «Резервные копии».

Алгоритмическая часть перенесена из SymPort ([PHONE_BACKUP.md](https://github.com/grayhex/s60modern/blob/main/docs/PHONE_BACKUP.md),
лицензия MIT, см. [REUSE_MATRIX.md](REUSE_MATRIX.md)); код написан заново на Rust, серверные задания,
Docker volumes, NAS и сеть **не используются**. Python не требуется.

## Хранилище и формат

Копии лежат в папке, выбранной в «Резервные копии → Хранилище» (по умолчанию — каталог данных приложения).
Каждая копия — отдельный каталог, имя которого выбирает ядро (`ГГГГММДД-ЧЧММСС[-метка]`; путь от UI
не принимается):

```
<хранилище>/20261109-120000-метка/
  manifest.json      схема yeskia.backup/1: label, created_at_ms, source_kind, complete, interrupted,
                     total_files/bytes, files[{path,size,sha256,mtime_ms}], skipped[{path,reason}], exclude[]
  manifest.sha256    SHA-256 манифеста (защита от подмены/повреждения)
  files/…            содержимое
```

Абсолютный путь источника и идентификаторы телефона в манифест **не записываются** (только `source_kind` =
`folder` | `device` и пользовательская метка).

## Создание (create)

- Источник: папка на компьютере (любая) или папка подключённого устройства (только если матрица возможностей
  соединения не блокирует `files.read`; недоступное честно блокируется, WPD — только чтение).
- Потоково (блоки по 256 КиБ), SHA-256 на лету, mtime сохраняется; файл, изменившийся во время копирования,
  в манифест не попадает и заносится в «пропущенные».
- Symlink не обходится, не-обычные файлы, небезопасные имена Windows, слишком длинные пути (>1024) и глубина
  (>64) пропускаются с причиной. Любой пропуск ⇒ `complete: false` («неполная»).
- Лимиты: 200 000 файлов / 64 GiB, запас свободного места 5 %; отказ записи в непустой каталог и внутрь источника.
- Пути на Windows открываются с префиксом `\\?\` (длиннее 260 символов).
- Отмена / отключение / ошибка: остаётся копия с `interrupted: true` и уже скопированным; она так и
  помечена в списке и **не принимается** как полная.
- После создания копия сразу перечитывается и проверяется по хешам.

## Проверка (verify)

Перечитывает все файлы и сверяет SHA-256 и размер. Отчёт: манифест цел/повреждён, **повреждённые**,
**отсутствующие**, **лишние** (в `files/`, но не в манифесте), **небезопасные пути** в манифесте.

## Восстановление (restore)

1. По умолчанию — **dry-run**: план «новый / совпадает / конфликт / заблокирован» по каждому файлу, без записи.
   Можно ограничить путём внутри копии. Копия сначала проверяется целиком; повреждённая не восстанавливается.
2. После **отдельного подтверждения** пишутся **только новые** файлы: конфликты не перезаписываются,
   ничего не удаляется. Запись — во временный файл, атомарное размещение без перезаписи, затем обратное
   чтение и сверка SHA-256. Если за время работы файл появился — он остаётся нетронутым (`raced`).
3. Восстановление на устройство — тот же путь через Device Core: первое согласие на запись, очередь, отмена,
   отключение ⇒ `uncertain`, автоповтора нет. Запись на WPD не заявляется (`unsupported`).

Защита: относительные пути из манифеста проверяются (`..`, абсолютные, `\`, зарезервированные имена Windows,
символьные ссылки при выходе из корня) до любой записи.

## UI

Список копий (дата, файлов, размер, состояние: полная / неполная / прервана / манифест повреждён), выбор
источника и папок, исключения, метка, прогресс «файлов X из Y», кнопка «Остановить», «Проверить»,
предпросмотр восстановления, подтверждение записи, «Сохранить отчёт» (JSON, без имён файлов и приватных
данных, как и остальные отчёты).

## Миграция копий SymPort

Формат SymPort (`symport.backup/1`) намеренно **не читается** напрямую: схема другая, и принимать чужой
манифест без проверки нельзя. Перенос вручную: «Создать копию → Папка на компьютере» с источником
`<старая копия>\files` — YESKIA создаст новую копию в своём формате с новыми хешами. Формат
`yeskia.backup/1` версионирован; изменение схемы — новая версия с явной проверкой при загрузке.
