# Рингтоны, подготовка медиа и темы (issue #9)

> Всё выполняется **на этом компьютере**: файлы не загружаются на веб-сервер, временных серверных копий
> нет (в отличие от браузерного SymPort). Результат — файл в выбранной вами папке. Это **не** утверждение, что
> он воспроизводится или устанавливается на телефоне: передача, установка и проверка на Nokia — отдельные шаги.

## Состояния результата

Приложение различает четыре состояния и показывает их на странице «Медиа и темы»:

| Состояние | Кто устанавливает | Что показывает приложение |
| --- | --- | --- |
| `generated` | приложение | файл создан и **перечитан** (ffprobe + SHA-256 после размещения) |
| `transferred` | приложение | файл записан на телефон (`files.upload`, без перезаписи) и проверен обратным чтением; только при доступной записи на соединении |
| `installed` | пользователь на телефоне | «приложение этого не определяет» |
| `verified on phone` | пользователь | «не подтверждено» |

## FFmpeg: внешний инструмент

Решение по стратегии: тяжёлую обработку (декодирование, MP3, нормализация громкости, H.264/MPEG-4, картинки)
**не переписываем на Rust** — это внешний процесс FFmpeg, как в SymPort (там он тоже был отдельным процессом).
Reuse алгоритма из Python (`symport/audio/studio.py`, `symport/revive/media_prep.py`, MIT) — параметры, пределы,
двухпроходная `loudnorm`, пресеты; обёртка и проверки — на Rust (`crates/yeskia-core/src/media.rs`).

- **Не входит в приложение** и им не обновляется. Поиск: папка из «Указать папку FFmpeg…» → `tools\ffmpeg` и
  `ffmpeg` рядом с приложением → `PATH`. Нужны `ffmpeg` и `ffprobe`.
- Версия и лицензия сборки определяются по `ffmpeg -version` (`--enable-gpl`, `--enable-version3`,
  `--enable-nonfree`) и показываются; сборка `nonfree` помечается нераспространяемой. Установщик (issue #11)
  должен либо не включать FFmpeg, либо включить сборку с подходящей лицензией и приложить её текст и исходники
  (для GPL-сборок — по условиям GPL); версия тогда фиксируется в установщике.
- Нет FFmpeg или нужного кодека (`libmp3lame`, `libx264`, `mpeg4`, `aac`) → ошибка `TOOL_MISSING` с понятным
  текстом; рингтоны и подготовка недоступны, анализ тем работает.
- Запуск **без оболочки**: числа и перечисления проверяются, пользовательских строк в аргументах нет, пути
  абсолютные. Разрешены только `file` и перечисленные демультиплексоры (сети, плейлистов и пользовательских
  фильтров нет). Окружение очищено; на Windows процесс без окна.
- Пределы: вход ≤ 64 МиБ, ≤ 10 минут, ≤ 40 Мпикс; выход ≤ 64 МиБ; таймауты ffprobe 20 с, аудио 80 с, видео 240 с;
  вывод процесса ограничен; **отмена** убивает процесс; временный файл `.имя.yeskia-part-…` удаляется всегда.
- Ограничение: FFmpeg получает обычный путь (не `\\?\`), поэтому пути длиннее 260 символов на Windows он не откроет.

## Рингтон

Выбор файла (аудио или видео со звуком) → проверка (ffprobe) → волна (декодирование в моно 8 кГц, до 4000
отрезков) → обрезка по секундам, нарастание/затухание, моно, выравнивание громкости (двухпроходная LUFS),
битрейт и частота → «Создать рингтон…» (диалог сохранения; **существующий файл не перезаписывается**).
Заготовки: «Рингтон» 30 с / MP3 моно 128 кбит/с, «Сигнал» 5 с / 96 кбит/с. Результат можно прослушать в окне
(встроенный предпросмотр до 8 МиБ). Тишину нормализация не делает громче; затухание может снизить итоговую громкость.

## Подготовка медиа

Пресеты: видео (MP4 H.264 baseline 320×240, 3GP MPEG-4 176×144), аудио (MP3 128 / 64 моно, AAC 96), картинки
(обои — обрезка под экран, фото — вписывание, JPEG/PNG). Размер картинок берётся с **экрана выбранной модели по
документации** (E52 240×320, E72 320×240, N95 240×320, N97 mini и N8/E7 360×640, 7610 176×208); без выбранной
модели картинка не готовится. Автоматически совместимость не приписывается: пресеты теоретические
(`hardware: not-tested`), размеры экрана не измерялись на телефоне.

## Темы S60

Импорт: папка темы, один из файлов `.skn/.mbm/.mif/.pkg` или SIS (с компьютера либо из библиотеки пакетов).
Проверки (порт `tools/s60/s60inspect.py` и `symport/theme/inspect.py`): структура `.mbm` (UID, trailer, заголовки,
размеры данных, RLE-распаковка всех растров), `.mif` (UID/версия, таблица, каждый индекс указывает на растр,
все растры задействованы), `.skn` (длина, PID1, имена), пакет (UID, пути установки, зависимости поддержки
скинов, поставщик), согласованность UID пакета и `.skn`, класс диапазона UID, **геометрия** крупнейшего растра
относительно экрана модели (E52 240×320 совпадает; E72 — «другая ориентация, автоматически не подходит»).
Принятие прошивкой и установка — всегда `unknown`/`not-tested`.

Предпросмотр — растры из `.mbm` (с маской, если за цветным растром идёт 8-битная серая того же размера); это не
снимок экрана телефона и не воспроизведение системного интерфейса Symbian. Показаны основные цвета наибольшего
растра с контрастом WCAG на белом и чёрном.

**Не реализовано:** редактирование/сборка темы, компиляция скина, `makesis`/`signsis`, подпись (внешние
инструменты; приложение ничего не подписывает «невидимо»), Theme Studio SymPort, N97 mini / Symbian^3 темы.
