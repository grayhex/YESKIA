# Задание агенту: редизайн YESKIA под Windows 11 Fluent

## Цель

Превратить текущий Soft UI в выразительное, быстрое и удобное **Windows 11 desktop-приложение**, сохранив название/существующий логотип YESKIA, идентичность классической Nokia (`#124191`), весь текущий функционал и архитектуру **Tauri 2 + Rust + React/TypeScript**. Два рабочих дизайн-референса: [главный экран](assets/overview-preview.webp) и [файловый менеджер](assets/filemanager-preview.webp); [интерактивный макет](prototype.html).

## Где работать

- Оболочка: `ui/src/components/Shell`, `ui/src/App.tsx`, `ui/src/styles/*`.
- Страницы: `ui/src/pages/{HomePage,FileManagerPage,DevicePage,PersonalPage,StorePage,StudioPage,CertificatesPage,BackupsPage,SettingsPage,WelcomePage,JournalPage}`.
- Текущие ассеты: `ui/src/assets/brand/yeskia-logo.png`, `ui/src/assets/phones/`, `ui/src/phones/registry.ts`.
- API, модальные окна, статусы, операции и безопасность **не переписывать ради дизайна**.

## Функциональные требования

**P0 — shell и главная**
1. Создать единые Fluent-подобные дизайн-токены: цвет, поверхности, текст, разделители, hover/focus, compact spacing, таблицы, кнопки и статусы. Синий Nokia является основным бренд-цветом, остальные цвета используются **семантически**. Предусмотреть light/dark, reduced motion, масштаб DPI.
2. Нативно выглядящие шапка/заголовок окна, компактная боковая навигация с иконками и сворачиваемыми группами, основное содержимое и статусная строка. **Не рисовать фиктивные кнопки закрытия/сворачивания вместо реально работающего окна**; использовать штатное поведение Tauri/Windows и аккуратно согласовать с текущим titlebar.
3. Обновить HomePage: крупное корректное изображение **выбранной/идентифицированной модели**; состояние устройства и транспорта; 2–4 быстрых действия только если доступны; блок последних *реальных* операций; компактные сведения о доступных функциях. Если телефон не найден — красивый empty state с кнопкой диагностики. Никаких придуманных процентов батареи, памяти, последних бэкапов и истории.
4. Разграничить состояния «обнаружен в USB/WPD», «идентифицирован», «подключён», «функция проверена/доступна», «нет транспорта», «mock/demo». Не объявлять PC Suite доступным по одному VID/PID. Беречь данные пользователя.

**P0 — файловый менеджер**
5. Две полезные панели «Компьютер / Телефон» с независимой навигацией, breadcrumbs, сортировкой, поиском по текущей папке, выделением, размером/типом/датой и отдельным scroll. Не заменять локальный файловый менеджер веб-сервисом или плитками.
6. Понятные команды копирования, скачивания, открытия, обновления, отмены; клавиатурное управление и подсказки, контекстное меню там, где действие реально реализовано. Глобальная очередь/прогресс только на основе фактических операций.
7. Чётко отражать режимы: WPD/MTP read-only, накопитель read/write при подтверждении, отсутствующие маршруты. Недоступные действия disabled с объяснением. Сохранить отказ от silent overwrite, отмену, ошибки частичного переноса, защиту от повторной записи.

**P1 — остальные страницы и качество**
8. Привести к единым компонентам «Подключение/Диагностика», «Контакты», «SMS», «Календарь/Задачи», «Приложения/Установщики», «Медиа/Темы», «Сертификаты», «Бэкапы», «Настройки», «Журнал», Welcome. Избегать огромных пустых hero-карточек, не внедрять фейковые функции.
9. RU/EN на всех новых строках через `i18n`; light/dark по ОС; логичные tab order, Esc, focus visible, aria labels; системные диалоги для путей и экспортов. Демо-пометки только в демо-режиме.
10. На 1500×900 и 1366×768 основные действия видны без «простыни»; длинные таблицы прокручиваются внутри рабочих панелей. 100/150/200% масштаб, narrow/window resize без горизонтального обрезания и потери функционала.
11. Убедиться, что при переключении устройства и экранов запросы отменяются/отбрасываются так же, как сейчас. Не ломать тесты состояния модалок/обновлений/передач. Не вводить облако, логины, сторонний трекинг или новый backend.

## Проверка и критерии приёмки

- Актуальный логотип и исходные графические ассеты загружаются локально; цвет классической Nokia `#124191`; визуально близко к макетам, а не к прежнему soft-neumorphism.
- Home и File Manager сверены с приложенными макетами и состоят из реальных компонентов, а не зашитой картинки/iframe прототипа.
- Экран без телефона и устройство, обнаруженное лишь как MTP, **не выдают** доступ к SMS/контактам/записи; не используют макетную фикцию.
- Файловый менеджер безопасен при повторе и коллизиях, работает клавиатура и отмена операций; существующая логика остаётся.
- Снимки реального UI из запущенного приложения для главной и файлов (состояния без устройства и с mock), светлая/тёмная тема, 1500×900 и 1366×768.
- Проверить: `npm run ui:test`, `npm run ui:typecheck`, `npm run ui:lint`, `npm run ui:build`; существующие профильные Rust тесты по затронутому коду. Не считать браузерные скриншоты доказательством работы на физической Nokia.
- Приложить краткое before/after, перечень реальных UI-переключателей и оставшихся ограничений.

## Процесс

Один сфокусированный PR либо поэтапные PR с связью с issue. Сначала shell/tokens + Home, затем файлы, затем остальное. Не менять устройство/протоколы/DB без необходимости. **Не merge и не deploy автоматически**, PR на ревью владельца.
