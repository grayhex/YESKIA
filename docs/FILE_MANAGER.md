# Desktop File Manager (issue #5)

Сценарий: **открыл телефон → увидел доступные файлы → скачал → проверил**. Это настольный файловый менеджер
с двумя панелями (компьютер | телефон), а не копия веб-браузера файлов SymPort: библиотека
`@harryy/react-file-browser` и веб-API не используются.

## UX

- Две панели: файловая система Windows и хранилища телефона. Таблицы с сортировкой, фильтром по имени,
  скрытыми файлами, **множественным выбором** (клик, Ctrl/Shift+клик, Ctrl+A, Пробел).
- Клавиатура: ↑↓ Home End — перемещение, Enter — открыть папку, Backspace — вверх, F5 — обновить,
  Ctrl+C / Ctrl+V — копировать между панелями, Shift+F10 / клавиша меню — контекстное меню.
- **Drag & drop** между панелями (HTML5; для этого в `tauri.conf.json` у окна `dragDropEnabled: false` —
  перетаскивание файлов из Explorer в окно приложения не поддерживается), **контекстное меню**, прогресс и
  отмена очереди.
- Нативные диалоги Windows (`tauri-plugin-dialog`): «Выбрать папку…», «Скачать как…» (Save), «Выбрать файл
  для загрузки…» (Open). «Показать в проводнике» — `explorer.exe /select,…` (ничего не запускает и не открывает).
- Коллизии имён: по умолчанию **ничего не перезаписывается**. Диалог: пропустить / сохранить под другим
  именем (`имя (1).ext`) / заменить (явное решение) / применять ко всем следующим. Esc = пропуск.
- Кириллица и любой Unicode в именах; большие файлы передаются потоком по 256 КиБ с прогрессом
  (в памяти не накапливаются); поддерживается отмена и обрыв связи.
- Скачивание папок рекурсивно (папки создаются слиянием, файлы — без перезаписи). Загрузка папок пока не
  поддерживается. Удаления/переименования нет вообще.
- Ассоциации файлов и предпросмотр **не реализованы** (открытие файла из приложения не делается, чтобы не
  запускать исполняемые файлы); решается отдельно при необходимости.

## Безопасность и проверка

- **Скачивание**: данные пишутся во временный файл `.имя.yeskia-part-…` рядом с целью; размер сверяется с
  размером на устройстве, SHA-256 считается на лету, файл размещается атомарно без перезаписи (жёсткая
  ссылка; на ФС без неё — проверка+переименование), затем **читается с диска и сверяется SHA-256**.
  При сбое/отмене/отключении временный файл удаляется — под настоящим именем частичного файла не остаётся.
- **Загрузка** (`files.write`): только если матрица соединения не `unsupported`; перед **первой записью на
  соединение — явное согласие**; потоковая запись в временный файл на томе и атомарное размещение; затем
  обратное чтение и SHA-256. Сбой/отмена записи → `uncertain`, **очередь останавливается**, автоповтора нет.
- Пути устройства и компьютера проверяются до очереди: без `..`, `\`, управляющих символов, зарезервированных
  имён Windows; пути хоста — абсолютные.
- Никаких контактов/SMS и «диска C:» телефона: WPD показывает только то, что вернул сам телефон; PIM —
  `unsupported` (нет доказанного транспорта).

## Режимы

| Режим USB | Что видно | Запись |
| --- | --- | --- |
| **Mass Storage** | Тома, **привязанные к этому устройству** через PnP-цепочку (`E:/…`, `F:/…`); корень `/` при нескольких томах показывает сами тома. Выйти за их пределы нельзя: чужие диски, `..`, симлинки наружу отвергаются (`VolumeFileProvider`). | Доступна (`not-tested` до первой операции), только после согласия |
| **WPD/MTP** | Хранилища и папки телефона (`/Phone memory/DCIM`), **read-only** листинг и скачивание (`IPortableDevice` с `GENERIC_READ`) | **Не заявляется** (`unsupported`), кнопок записи нет |
| COM / неизвестный режим / нет драйвера | Файлы недоступны; показывается причина и переход в «Диагностику» | — |

Mock-устройство ведёт себя как Mass Storage-подобное (диск `E:/`), везде помечено MOCK.

## Архитектура

- Ядро: `fsutil` (имена, временные файлы, размещение, SHA-256), `host` (локальная ФС), `volume` (том с «клеткой»),
  `FileProvider::read_to/write_from` (потоково), операции `files.download` / `files.upload` в `Engine`
  (очередь, отмена, таймауты, fingerprint — как у остальных, см. DEVICE_CORE.md).
- Обнаружение: `PnpTransport` — файловый провайдер по режиму устройства; WPD-бэкенд (`wpd_list` / `wpd_read`)
  в `windows_impl.rs`; поддельное WPD-дерево в `fake.rs` для тестов.
- Tauri: `host_roots`, `host_list_dir`, `host_create_dir`, `reveal_in_explorer`, плагин диалогов.
- UI: `pages/FileManagerPage.tsx`, `fm/*` (панель, меню, диалоги, очередь передач, пути).

## Статус приёмки

| Пункт | Статус |
| --- | --- |
| Все операции и отмена на mock volume (скачивание, загрузка, коллизии, отключение, отмена, Unicode, большой файл) | `tested-on-mock` / `tested-on-host` (тома на реальной ФС хоста) |
| Mass Storage: границы тома, привязка к устройству, copy → read-back SHA-256 | `tested-on-host` (временные папки), **на реальной карте телефона — `not-tested`** |
| WPD/MTP read-only листинг и скачивание | `implemented` (компилируется под Windows, логика на поддельном дереве); **на реальном телефоне — `not-tested`** |
| Нативные диалоги, «Показать в проводнике», drag & drop в WebView2 | `implemented` (собирается в CI на Windows; поведение на живой системе вручную не проверялось) |
| Физическая проверка на Windows WPD/MTP телефоне и Mass Storage карте | **не выполнена: нужно железо** |

### Как закрыть аппаратную часть

1. WPD/MTP (например, `0421:0223`): подключить, «Диагностика» → «Сохранить отчёт»; в «Файлах» открыть хранилище,
   скачать небольшой файл, убедиться в метке «проверено: размер и SHA-256». Если листинг не работает — приложить
   код ошибки из отчёта (причина unavailable документируется, «поддержка» не заявляется).
2. Mass Storage: режим «Mass storage», скачать файл, затем (осознанно) загрузить тестовый файл на карту и
   убедиться в обратном чтении; отключить кабель во время передачи — частичных файлов остаться не должно.
